**Uniform reduction arguments.** Write `Z_R = cons K R`, `U_n(N) = 1ⁿ0 ++ N`, and `r = U_(n−1)(N)` in the variable branch. The following identities suffice for every row:

| Expression | `s = Z_R` | `s = U_n(N)`, `n ≥ 1` |
|---|---|---|
| `s (λq.c)` | `c R` | `c r` |
| `s I` | `K R` | `I` |
| `s K` | `K` | `F` |
| `s F` | `R` | `r` |
| `s s` | `K R` | `K N` |
| `s D` and `s (s K)` | `K` | `r` |
| `s (λb.b F)` | `F` | `r` |
| `s I s` | `R` | `s` |
| `s I (s s) next` | `R next` | `N` |

The only unbounded step here is the standard equal-index diagonal: `U_0(N) U_0(N) →* K N`, and `U_(m+1)(N) U_(m+1)(N) →* U_m(N) U_m(N)`. Therefore `U_m(N) U_m(N) a →* N` for every `m ≥ 0` and every argument `a`. All other identities are fixed cell/Boolean reductions. A variable tail is always a Scott cell, including `r = U_0(N)` at index one. Thus rebuilding it as `λh.r h` or `λh.h (r K) (r F)` is beta-correct on these inputs; no free-tail eta equality is assumed.

For the two constant-stream constructions, `T = K(K X)` satisfies `T H (T T T) →* X`, so `RDR T →* X` for arbitrary rigid `X`. Row 43 transforms only the variable branch into that instruction; row 44 transforms only the zero branch. The original stream is retained in the other branch.

20. **20_projected_dual (dual operand).** A projected Boolean selects between tail application and diagonal forcing; neither arm binds the tail.
21. **21_predecessor_dual (conditional predecessor).** Only in the variable branch, both conditional predecessors equal r; their diagonal is K N. The zero branch erases them.
22. **22_pred_adaptive_handler (conditional predecessor).** s D is K at zero and r at a variable. The adaptive operand is R next or a two-field constant returning c r.
23. **23_false_pred (conditional predecessor).** The head is F at zero and r at a variable. F keeps the dual operand; r opens the constant handler to produce c r.
24. **24_reference57 (cell-borrowed dispatch).** The known beta-prime witness: zero selects the drop-and-apply handler; the variable tail opens a constant handler.
25. **25_reference65 (cell-borrowed dispatch).** The known delta witness: s b is K or r, while a separate opening retains the original tail.
26. **26_projected_pred (cell-borrowed dispatch).** s (s K) is K at zero and r at a variable. It controls the same adaptive result/handler interface without a source diagonal lambda.
27. **27_projection_dispatch (projected Boolean).** Project the first bit to choose the two complete computations; the variable return uses stream-owned applications.
28. **28_projection_tail_return (projected Boolean).** Under the variable selection, the projected tail is a cell whose fields can be discarded to produce c of another tail projection.
29. **29_projection_pred_skip (projected Boolean).** Only the selected variable arm diagonalizes conditional predecessors; the whole stream is its erased force.
30. **30_projection_cross_skip (cross application).** The variable arm cross-applies s to the conditional R-or-s object, which equals s there; next is erased there.
31. **31_reboxed_tail (rebuilt tail).** The returned tail is rebuilt by opening s inside a fresh handler lambda. On a variable r is a Scott cell, so the reconstruction beta-reduces to r.
32. **32_projected_rebox (rebuilt tail).** A variable tail is a cell; independently projecting its bit and remainder rebuilds that exact cell, including at index one.
33. **33_function_operand (callback operand).** Pass the entire variable action as a final operand. The selected Boolean decides whether to apply it to the original tail.
34. **34_callable_suffix (callback operand).** The operand is a constant suffix function K R or K N; force it with s at either use.
35. **35_cps_suffix (CPS operand).** A CPS suffix receives application-to-next at zero, or the partially applied return continuation at a variable.
36. **36_pair_operand (pair operand).** The operand packages tail and skip. The zero callback ignores the skip; c consumes both in the variable branch.
37. **37_diagonal_callback (callback operand).** Self-apply the variable callback, using the callback itself only as the erased force of r r.
38. **38_tail_supplied_force (input-owned callback).** The variable tail supplies its own bit d and suffix t to the callback; the final operand restores the whole original tail, and d forces its diagonal.
39. **39_selector_packet (second-stage packet).** The packet maps the first bit to next or c. The zero branch uses it as a tag reader and the variable branch as the return continuation.
40. **40_action_packet (second-stage packet).** The packet stores zero action lambda r.r next and variable action c. Its selected action consumes the same original tail in either branch.
41. **41_cps_packet (second-stage packet).** The packet receives both the tag and a selected consumer; it supplies next or c to that consumer, using b as the variable skip force.
42. **42_reverse_packet (second-stage packet).** A reversed Church pair stores c before next; explicit selectors extract the requested component in the two branches.
43. **43_constant_var_return (constant-stream instruction).** Preprocess variables into K(K(c r N)) and leave zero streams intact. The 165 reader sends double constants to their stored result.
44. **44_constant_zero_return (constant-stream instruction).** Preprocess zero streams into K(K(R next)) and leave variable streams intact. The reader constant-stream identity supplies the other branch.

**What was checked.** [zoo.py](zoo.py) contains the 44 literal hand-written terms and their arguments. No grammar, Cartesian product, term enumeration, or candidate sweep was used. The small de Bruijn normalizer in the repository checked both reader laws before any splicing: `Z_R` with rigid `R`, and `U_n(N)` for `n = 1..16, 31, 64` with rigid `N`, `next`, and `c`. [zoo.json](zoo.json) records all probe counts, exact expanded bodies, bit costs, and normal-form hashes. The all-length reasoning is given above; these are hand reductions, not new Lean theorems.

Every full candidate was run through the actual repository command `python3 tools/self-interpreter/polish.py FILE.lam`. [run_polish.py](run_polish.py) only supplies resource controls and records the logs. A lane-local `sitecustomize.py` caps battery worker pools at two, points subprocesses at a frozen binary, and places compiler temporary files inside this lane. Letopt used its explicit two-thread option. Its configured budgets were three cuts plus a two-cut no-inline run for inputs through 175 bits, and two cuts for larger inputs. These are the requested polish operations, not an unrestricted search.

**Tooling detail resolved for the deliverable.** `polish.py` uses `--report-le 164`. Letopt can therefore print `smallest rendering ...: 169 bits` while its final `best` wire is still 173 bits: the histogram tracks all configurations, but `best_t` is updated only from rendered reporting hits (`src/cli/golf/letopt.rs`, lines 815–858). This does not hide a sub-162 result, because every such result would be inside the reporting threshold. To avoid presenting an unmaterialized size as a verified artifact, [collect.py](collect.py) rerendered each needed minimum with its own reporting threshold and at most two cuts, then battery-checked any wire not already checked as an input candidate. This required 6 new wire checks. [artifacts.json](artifacts.json) links every saved minimum to its actual battery log. The source tree was not modified to change this reporting behavior.

All 84 polish invocations completed without timeout or battery failure; the slowest took 21.922 seconds. Their summed wall time was 434.658 seconds. Individual letopt subprocesses had a 100-second cap and whole polish process groups had a 115-second cap. There was one active candidate job at a time. No other lane was written, and no agent was consulted. The frozen executable SHA-256 is `5266a7fc450c2bc6050a2baf7f7a23f06589fdf99a8a6470d73b83dcb324c112`.

**Assessment.** The successful cross-branch constructions really do have different source/stream ownership: output nodes may come from the first cell, from the variable tail, from a callback, or from a transformed constant stream. Several larger isolated readers shrink after let placement, confirming the reason to test complete splices. In this catalogue the extra tail binding, re-opening, or packet dispatch costs more than the sharing saves. That is an observation about these constructions, not a lower bound on readers or interpreters. The simplest dual operand remains the 164 control; the 162 control remains the only 162-bit result.
