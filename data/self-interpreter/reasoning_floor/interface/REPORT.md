# Interface lane: paired protocols, exact costs, and a return-arity collision

**No sub-165 interpreter found.** Four coupled designs and two controls pass
the exact battery. The smallest new pairing is **202 bits**: NEXT is the
reader's outer operand and continuations carry thunked remainders. A second
pairing really does use the otherwise discarded stream copy, as the argument
that forces an APP remainder thunk; it costs **213 bits**. The root shortcut
combined with that remainder convention costs **240 bits**.

The useful obstruction is an **actual-value collision**: in the ordinary
value protocol, `var n` and `I (var n)` with the same suffix produce
beta-identical closures. Therefore an internal continuation cannot consume an
extra argument only on the variable return while retaining the ordinary
constructor return. This proof does not replace the concrete values by rigid
placeholders. It also identifies its escape: preserve constructor provenance
in the value or continuation, or change both return conventions.

All new files are in this lane. No consult, subagent, term enumeration, or
tracked-file edit was used. The broad reader and NEXT optimality claims in
the supplied reports are not premises of the arguments below. In particular,
this report does not strengthen their conclusions to unrestricted optimality.

## 2. Equations and correctness of the constructions

Use `K = lambda a b.a`, `F = lambda a b.b`, `[b]r = lambda h.h b r`, and

```
cell(a,e) = lambda b r.b a (r e)
A(f)      = lambda e a.f (cell(a,e))
L(f,g)    = lambda e.f e (g e)
D_c       = lambda v t.c v (t t).
```

These abbreviations are expanded in the sources; they are not extra lets
hidden from the measurement. Every fixed point uses the ordinary shared
Curry diagonal. Write `U_n(R)=1^n 0 ++ R`; a variable's raw value is
`U_(n-1)(R)`. For every such tail `r`, `r r =beta K R`.

### A. NEXT operand plus thunked returns (202)

The internal equations are

```
P c s = s (lambda b r.b r (lambda u.c r (r r))) J_c
J_c d = P (lambda f.d (c A(f))
                        (lambda t.P (lambda g.c L(f,g)) (t t)))
E c   = P D_c.
```

On a variable, the reader reduces to

```
(lambda u.c r (r r)) J_c -> c r (r r) =beta c r (K R).
```

On a constructor `[K]q`, its Scott eliminator gives `q J_c`, so with
`q=[d]t` it gives `J_c d t`. The first parse returns its closure f and `K R`.
ABS forwards that thunk: `c A(f) (K R)`. APP forces it with itself and
parses R: `P (lambda g.c L(f,g)) R`. Thus the induction invariant is

```
P c (code(M) ++ R) =beta c V_M (K R),
```

with the ordinary closure semantics for V_M. At the root, `D_c` turns this
into `c V_M R`; for closed M, `V_M =beta lambda z.M`.

This couples two changes: the zero arm hands the stream directly to NEXT,
while the variable arm no longer uses that NEXT operand to force its rest.
The local saving is real but small. In the exact frame used in
`identities.py`,

```
lambda u.c r (r r u)    27 bits
lambda u.c r (r r)      23 bits.
```

The four saved bits are one application and its innermost occurrence. In
NEXT's corresponding frame, the APP parse changes from 37 to 50 bits:

```
P (lambda g.c L(f,g))
lambda t.P (lambda g.c L(f,g)) (t t).
```

The latter is the required forcing continuation for this explicit template.
The public adapter `D_c` is another 21 bits in frame `[c]`, before charging
its insertion. These are exact local costs of the displayed terms, not a
claim that every possible adapter or APP implementation has those costs.
The global letopt minimum is 202, the same numerical size as a previously
recorded thunk-rest interpreter; this is no improvement over that record.

### B. Use the trailing copy as the force operand (213)

Here the reader uses `s s`, not `s s s`, and the zero arm has one binder:

```
P c s = s (lambda b.b (lambda q.q J_c) c) (s s)
J_c d = P (lambda f t q.
             d (c A(f) t)
               (P (lambda g.c L(f,g)) (t q)))
E c   = P D_c.
```

On a variable, the result is again `c r (K R)`. On a constructor `[K]q`,
`[K]q ([K]q) = K q`, so the result is

```
q J_c (K q) = J_c d body (K q).
```

The first recursive parse returns `f, K R`, leaving the final `K q` on the
application spine. The three-argument callback consumes it. In ABS it returns
`c A(f) (K R)`; in APP the same argument forces `(K R) (K q) -> R` and starts
the second parse. The induction invariant and public decoding are the same
as in A. This is an actual joint repair: the extra argument is used at the
site introduced by the changed remainder protocol, rather than being dropped
by an additional standalone wrapper.

Its limitation is also exact: the forced thunk erases that argument. It does
not convey the constructor tag or any other state beyond that point. The
mode-erasure obstruction in section 3 describes this boundary.

### C. Thunked input and output (223)

```
P c T = (lambda s.s (lambda b.b (lambda q u.q J_c) c) (s s)) (T T)
J_c d r = P (lambda f.d (c A(f)) (P (lambda g.c L(f,g)))) (K r)
E c s   = P D_c (K s).
```

The internal law is `P c (K(code(M)++R)) =beta c V_M (K R)`.
The parser forces its input once; a constructor's first-child input is
wrapped by `K r`; in APP the returned thunk is already in the parser's input
format. ABS forwards it. The two public adapters establish the ordinary
contract. Moving the force from the APP callback to parser entry is valid,
but now raw first-child inputs and the public input require wrapping.

### D. Root enters NEXT directly (240)

Define the two interfaces by

```
P k s = s (lambda b r.b r (lambda u.k r (r r))) (N k)
N c d = P (lambda f.d (c A(f))
                        (lambda t.P (lambda g.c L(f,g)) (t t)))
E c s = s (lambda zero q.q (N D_c)).
```

The implementation puts the fixed point around N and defines P privately
inside that fixed point. For a closed input `s=[K][d]body`, the root equation
reduces directly to `N D_c d body`. The mutually recursive parser/NEXT
induction is exactly A's, so `E c s =beta c V_M R`. The known-zero root bit
really removes the ordinary first-bit dispatch at the entry. It does not
remove the thunked-remainder adapter or the private reader's recursion costs.
The measured combined design is 240.

### Controls (181 and 197)

For the ordinary-remainder delayed-drop control,

```
P c s = s (lambda b.b (lambda q.q J_c) c) (s s s)
J_c d = P (lambda f r q.d (c A(f)) (P (lambda g.c L(f,g))) r).
```

The extra q is consumed only after the first child's value and rest arrive.
This gives the standard parser law, with no root adapter. Its first-child
continuation has a different arity from both its parent and the APP
continuation. It is a concrete witness that those internal arities need not
all be binary when the handoff changes.

The function-environment control changes variable values to
`lambda e.e r` and the ABS cell to

```
E(a,e) = lambda s.s (lambda b.b (K a) e).
```

Then `E(a,e) ([K]R) -> a` and `E(a,e) ([F]r) -> e r`.
The usual variable and syntax inductions give correctness with the same APP
lift. Combining it with the delayed-drop callback costs another 16 bits,
both before and after the measured let optimization. This is a control
showing that merely combining two already expensive changes is insufficient;
I do not claim a new function-environment algorithm or a compensating saving.

All these are beta-reduction arguments, without evaluating the interpreted
program. Consequently their inductive reasoning includes divergent source
programs. None of these interpreter proofs was formalized in Lean here.

## 3. Exact identities and obstructions

### 3.1 Actual-value collision forbids a mixed-arity shortcut

**Hypotheses.** A source M is parsed to a value `V_M` and its actual suffix R.
The continuation used by the enclosing lambda is the same term k when its
body is `var 1` or `I (var 1)`; it does not additionally capture or receive
that body's original code. Variable returns add a nonempty trailing operand
list, while constructor returns use `k V_M R` without it. The canonical
value protocol is retained, or more generally the two values below are
beta-identical.

**Claim.** This cannot implement the root contract, whatever those trailing
operands are and whatever k's implementation is.

**Proof.** Let `r_N=[K]N` be the raw closure for `var 1`. The closure parsed
for the closed identity is `K I`, independently of its following code. The
ordinary APP lift therefore gives

```
V_(I (var 1)) = lambda e.(K I) e (r_N e)
             -> lambda e.r_N e
             -> lambda e.e K N
              =alpha r_N.
```

The final step is beta, not eta: r_N is an actual Scott lambda. The same
identity holds for every unary index, since its raw value is a Scott lambda.

The closed root programs `lambda x.x` and `lambda x.I x` must both return
`W = C (lambda z.I) N`. The constructor-body case forces
`k r_N N =beta W`. The variable-body case would then be
`k r_N N T1 ... Tm =beta W T1 ... Tm`. A reduct of the latter retains at
least `m+2` arguments at the rigid head C, whereas W has exactly two.
Church--Rosser excludes their equality. Contradiction.

This proves an all-size exclusion for the stated mixed-return family. It
also applies to the function-environment control: its variable value is a
lambda, and lifting `K I` over that value beta-reduces to it too.

**Boundary.** A constructor tag retained in the value breaks the collision.
So does a continuation that also receives/captures the original body code.
Changing both caller conventions, as A and B do, is outside the hypothesis.
The result is not a lower bound for arbitrary changed value protocols.

### 3.2 An outer argument cannot enter a lambda-valued payload

**Hypothesis.** A return has already become `C V N`, with C rigid, and the
extra stream copy is supplied outside that expression.

**Claim.** No change confined to V, including adding lambdas that could
ignore the copy, can absorb it.

**Proof.** The application is `(C V N) Q`, not `C (V Q) N`.
Every reduct retains the C-headed outer spine and its third argument. This
is a statement about application ancestry, independent of whether V has a
normal form. Thus the copy must be consumed before that return, or the
control protocol must change. Construction B consumes it in the first-child
continuation; putting an unused binder inside A(f) would not work.

This is the general rigid-spine fact behind the earlier failed one-binder
zero arm, not a new unrestricted impossibility theorem.

### 3.3 Forcing an ordinary remainder thunk cannot carry the mode onward

**Hypotheses.** The only occurrence of a carrier Q containing the dispatch
mode is as the forcing operand in `T Q`, with `T =beta K R`, and every other
live field is independent of that mode.

**Claim.** This use of Q cannot distinguish ABS and APP.

**Proof.** `T Q =beta R` for every Q. Replace every such occurrence by R;
the resulting expression is beta-equal and contains none of the mode.
There are actual closed programs requiring a distinction with the other
fields fixed: take the first parsed operand to be I, and set
`R=code(I)++N`. An ABS input `lambda x.I` with suffix R and an APP input
`I I` with suffix N have the same first closure `K I` and the same remainder
R after that first parse. Their required returns are

```
C (lambda z x.I) R
C (lambda z.I) N,
```

distinct beta-normal forms. Hence that otherwise identical post-parse state
cannot implement both cases after Q is erased.

The scope is deliberately narrow: a second use of Q, a different thunk
representation that retains it, or a mode captured in the callback escapes
it. Construction B retains d separately, which is why it is correct and why
its forcing operand does not also pay for the tag binder.

### 3.4 A unary return needs suffix information somewhere

**Hypotheses.** The only return field is a canonical closure `V_M`, and the
continuation and all remaining state are independent of the suffix.

**Claim.** No such interface can satisfy the contract even for M=I.

**Proof.** `V_I =beta K I` is independent of N. Thus the entire returned
expression is independent of the fresh free N. Reduction cannot create N,
whereas `C (K I) N` contains it at the root. This excludes deleting the
remainder parameter without encoding it in the value, callback, or other
state. The always-zero first bit supplies no suffix information.

`identities.py` checks 26 fixed identities/counterexamples (23 equalities,
three inequalities) and 18 divergent-program suffix probes. It also measures
the five displayed module costs. `identities.json` contains the exact closed
probes and normal forms; `identities.log` gives their verdicts. The symbolic
arguments above are handwritten, not Lean proofs and not independently

the impossibility statements.

## 4. What remains worth trying

The mixed-arity observation is more restrictive than "the root is rigid".
A variable return really cannot meet the public continuation directly, but
an ordinary constructor can erase its provenance before reaching exactly the
same internal continuation. `I (var n)` is the minimal witness. A useful
paired change must preserve enough provenance to avoid that collision, or
make every return follow a new convention.

Uniform thunking is a concrete way to do the latter. The constructions show
why its obvious synergies do not pay here: it removes a four-bit force from
one return site, but introduces forces at parser entry or APP and requires a
public adapter. Using the duplicate as that force operand works, but the
operand is then erased and cannot also carry the second tag. Starting at
NEXT removes an entry dispatch without removing those costs.

My next constructive target would be a value representation retaining a
cheap constructor discriminator *and* an already needed suffix/continuation
field, with a first-child callback that can use those fields directly.
The discriminator must survive `I (var n)` instead of beta-collapsing to the
variable representation. Merely changing the direction of environment
application does not accomplish that. A viable candidate must price the
public decoder simultaneously; none here makes it free.

I have no all-size obstruction for that tagged or code-sensitive family, and
no evidence from this lane that it can fit below 165. These constructions
close specific attempted savings, not the last constructive region itself.


The checker invokes `python3 tools/self-interpreter/polish.py FILE.lam` for
each candidate, then materializes the reported minimum and tests it.
`sitecustomize.py` limits the repository battery's otherwise ten-worker
executor to two, sets temporary-file placement, and optionally archives
polish's captured letopt output without changing it. Letopt itself is called
with `--threads 2`. The final per-candidate polish calls took about 2.0--4.3
seconds each; the fixed identity/suffix checks took less than a second.
